# Tickets / Issues Rules

## Always

- Always check for `.gitlab` or `.github` to check if the project has issue templates described there and use them or ask the user to choose.
- Always include `### description`, `### to do` and `### accept` sections when creating a new ticket if no issue template is available.

## Never

- NEVER create or add **labels** Issues or Tickets unless explicitly asked by the USER.
- NEVER change a ticket description or title without explicit instructions from the USER.
